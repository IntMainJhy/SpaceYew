# Website audit · 2026-10-22

This pass inspected website authentication/surface boundaries, account-scoped blog storage and file access, résumé extraction, review snapshots, publication/takedown, editor state, brand assets and repository publication scope. Existing tests for uploads, moderation, credentials, backups, content sanitization and account isolation were rerun. Findings identified in this pass were fixed; this is a scoped code and regression review, not a claim that no undiscovered issue exists.

| Finding | Resolution |
| --- | --- |
| Blog management routes redirected back to the public owner profile | Independent `/workspace/blog` editor; `/blogs` retains the owner’s public default; owner editing uses `/admin/blog` |
| Member profile normalization dropped structured résumé content | Validated sections, metrics, translations, certificate/gallery collections and public PDF persist per account |
| Nested résumé images/PDF were missing from space ownership/reference handling | Account ownership, image/PDF MIME checks, historical references and fixed review snapshots cover nested media; private drafts remain private |
| Shared experience sessions could reach private workspace operations | Private spaces require real account authentication; subsequent community cleanup removed experience sign-in entirely |
| Save-state comparisons treated normalized object ordering as unsaved changes | Editor baseline uses the displayed normalized layout; successful save clears the dirty state; browser verification covers edits and preview |
| Owner profile could change through the existing admin form while another editor was open | Owner profile fingerprint plus space revision reject stale saves; member revisions remain optimistic and account scoped |
| Admin origin redirected SVG/Apple/brand files to the platform origin | Precise asset allowlist; split-surface HTTP checks confirm same-origin delivery |
| SVG metadata assets are cached as immutable for one year | BrandMark uses a generated SVG content hash in its URL; canonical SVG, ICO and raster consistency tests prevent stale exports |
| Word extraction pulled in a vulnerable CLI dependency chain | Replaced Mammoth with JSZip and XML-mode plain-text extraction; reject custom entities and oversized declared ZIP expansion before extraction |
| Certificate evidence lacked a compact presentation | Contained 3-column desktop / 2-column mobile grid, captions and native keyboard-dismissable image dialog; identifiers/QR codes are masked in owner media before upload |

Résumé extraction remains local and bounded: 8 MiB input, 30 PDF pages, 2,000 ZIP entries, 12 MiB per entry, 40 MiB declared expansion, 20-second child-process timeout and 256 MiB V8 heap. The child process is not an operating-system sandbox. Uploaded originals are never attached for public download automatically.

## Verification

- `npm test`: 162 passing tests, including nested-media ownership/publication, member import authorization, stale saves, CSRF, Word entities/expansion and generated brand assets.
- `npm run typecheck` and `npm run build`.
- `npm run test:homepage:http`, `npm run test:resume:http`, `npm run test:blog-editor:http`: built-server upload/extraction, authentication, editing, review, publication, public media access and takedown.
- `npm audit` and `npm audit --omit=dev`: zero reported vulnerabilities at the time of this pass.
- Real browser checks at 1135×788 and 390×844: independent fixture account, saved introduction/project changes, updated preview, cleared unsaved state, bilingual editor, compact certificate layout and Escape-to-close dialog. Immutable asset caching was reproduced and addressed with the versioned URL.
- Private owner content was updated only in application storage with a backup and unchanged account/session fingerprints. Certificate originals, local databases, environment files, native clients and installers are excluded from public commits.

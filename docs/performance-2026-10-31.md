# 全站高刷新性能优化与验收（2026-10-31）

## 交付目标与边界

移除应用自己的15/30fps限速，让可见的活动动画跟随浏览器requestAnimationFrame；按120/144Hz合成调度验证，并在本机160Hz环境做实际浏览器采样。静止内页、离屏、隐藏标签、暂停和减少动态偏好继续按需停止绘制，不通过空转“凑帧”。录屏素材原始内容是24fps，本次没有将重复视频帧冒称为120fps内容。

不能保证任意设备、尺寸、浏览器及电源状态始终超过120fps。下面的实测是短时本地实验；WebGL绘制提交率不等同于已完成GPU呈现的物理帧率，回调CPU时间也不等同于GPU耗时。

## 本机可见页面的高刷实测

Apple M5、160Hz显示设置；当前内置浏览器实际视口622×959 CSS px，DPR=2。使用仅限回环地址的只读临时代理，把相同探针注入优化前后真实页面，保留原CSP nonce。代理和统计面板没有接入生产应用、没有上传遥测或写入账号数据，验收后关闭。

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 首页玻璃（2秒窗口） | RAF约159.9Hz，但仅15次WebGL绘制提交/秒 | RAF约160Hz，160次WebGL绘制提交/秒 |
| 资源卡动画（2秒窗口） | 未在原生窗口单独采集 | 约159次绘制提交/秒 |
| 布料动画（2秒窗口） | 源码固定30fps上限 | 约159.9次绘制提交/秒 |

首页优化后回调CPU耗时P95约0.30ms；资源卡与布料采样分别约0.50ms和0.40ms，探针在该窗口未记录到50ms长任务。这里是包含仪表开销的RAF回调CPU提交时间，不能据此宣称GPU全帧仅需0.30ms。结果限定于上述尺寸和设备，没有用视口覆盖设置假装完成大尺寸桌面硬件测试。

最初Ego托管测试空间出现约31–37ms和1秒调度间隔，即使准备前台也未得到可信高刷节奏；该组FPS不作为性能达标证据。改用当前可见内置浏览器后得到上表。Ego仍用于桌面/手机实际WebGL、资源加载、功能和布局检查。

## 具体改动

- 首页/内页共享生命周期、kinetic、布料、后台SVG移除固定帧率门槛，按真实delta推进；指针阻尼不随刷新率加速。高刷发生持续漏帧时调整像素预算，保留每次显示回调的渲染机会。
- 滚动与缩放合到一帧，批量读取布局后再写样式；指针使用已测边界，重复reveal不再重新生成曲面和上传buffer。50px页头标志使用小型透射目标，透明主通道跳过整屏背景计算；首屏和展开玻璃恢复原光学分辨率。
- 布料位置与解析法线、资源卡粒子运动移至GPU；不再每帧CPU逐顶点计算并上传位置/法线。布料保留原运动方程，静态拾取代理与语义链接保留交互。
- 内页/资源卡的r187 RGB透射由每通道8次bicubic读取改成1次硬件mip过滤，保留RGB体积射线、IOR、色散、粗糙度LOD和版本/模板降级；不全局修改Three shader。
- 资源卡在邻近阶段异步预热shader；博客旅程离屏不建立GPU，预览纹理刷新合帧，重复尺寸不重建渲染目标；销毁取消未完成任务。
- 首页入场动作只在元素入屏时创建，移除不必要的ScrollTrigger及媒体/字体引起的全局refresh。原视频、拖动、暂停、减少动态和离屏释放保留。
- 客户端路由边界用React.lazy/Suspense按页拆分后台、编辑器、社区应用及博客主题，保留流式SSR及服务端权限检查。实际QA发现next/dynamic的无nonce预加载链接被strict-dynamic正确拦截，已换用兼容的React懒加载；没有削弱CSP。

## 验证

- 315项单元/运行时回归、类型检查、生产构建通过；包含120/144Hz热身与持续隔帧、自适应像素但不跳回调、跨刷新率同秒姿态、GPU buffer不重复上传、暂停/后台/离屏/reduced/print/contextlost/晚到加载及幂等释放。
- 4组隔离HTTP回归通过：唯一站长账号与后台权限、博客/发布/私密隔离、资源文档与多语言、社区与越权保护。测试使用临时数据，不修改真实站长账号。
- 七类公开页面实际加载无资源错误、破图或横向溢出；桌面/手机实际GLSL、布料与资源卡外观、资源卡暂停/恢复通过。独立源码复核通过。
- 本地探针有取消句柄与generation保护，测试覆盖连续采样不复活旧RAF链，无draw的回调不虚计绘制帧；探针仅作为开发脚本，不由应用导入。
- R3F现有依赖会输出一次Three.Clock弃用提示，属于上游兼容提醒，未屏蔽日志、未为消除提示而升级依赖。没有GPU shader编译错误或运行异常。

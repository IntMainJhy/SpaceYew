# 简历转博客主页

站点所有者可在**管理中心 → 个人资料与经历**上传 PDF、DOCX、UTF-8 TXT 或 Markdown 简历。先检查提取文字，可修改文字并重新生成，再填入资料草稿。只有点击“保存更新”才公开，上传和解析不会直接发布。

PDF 使用 [Mozilla PDF.js](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html) 提取，并按页面坐标重组分字体输出的文字，避免混合字体导致字序错乱。导入器在本地提取文字，按常见中英文标题划分教育、技能、工作、项目等栏目；不调用外部 AI、不自动翻译、不推断缺失日期，也不核验成果真假。扫描件需要先做 OCR，复杂分栏简历可能需要手动修正。应用新草稿会清除旧的资料翻译，请在语言标签中填写新版本。完整资料、栏目、数字亮点、证书和图片可在[博客编辑器](blog-editor.zh-CN.md)中新增、替换、排序和移除。

有结构化简历时，所有者的 Anx 页面展示教育、经历、项目、开源、荣誉等栏目，替代旧的作品内容列表；没有简历的现有主页维持原展示逻辑。`/blogs` 和所有者原有分享地址使用同一份资料，公开页不增加管理面板。

## 隐私与下载

原始上传文件保持未引用、非公开。解析会尝试移除常见手机号与身份字段，但不能代替人工隐私检查。需要公开下载时，在“公开下载的简历 PDF”选择单独脱敏的 PDF，保存后才对访客开放。原件保留在文件管理中，可由所有者删除。

`POST /api/admin/resume/import`（`fileId`）及 `/api/admin/resume/parse`（`text`）仅接受现有所有者管理会话，沿用同源校验。发布使用原有资料保存接口和审计记录。

## 处理限制

文件不超过 8 MiB，PDF 不超过 30 页。DOCX 解压前检查中央目录：最多 2,000 项、每项 12 MiB、声明解压总量 40 MiB。文字提取在短期 Node 子进程中执行，限制 20 秒、256 MiB V8 堆；每个服务进程最多同时处理 2 份文件，每个账号每小时最多提取 20 次。此为资源限制，不是操作系统沙箱；应用应以非特权账户运行。不会执行文档脚本或宏。

部署时须保留 `src/lib/resume-extract-worker.mjs` 及锁定的 npm 依赖，工作目录为应用根目录。解析器在 Next.js 请求事件循环之外运行。

验证命令：`npm test`、`npm run typecheck`、`npm run build`、`npm run test:resume:http`。

个人简历、PPT 原件、用户照片及真实数据库均保存在私有存储，不放入公开仓库。

成员通过真实账号登录后使用 `/api/spaces/resume/import` 和 `/api/spaces/resume/parse`；文件提取仅接受本账号上传的文件。成员草稿和原件保持私有，另行提交审核后才发布。DOCX 使用 JSZip 和 XML 文本解析器提取正文，拒绝自定义实体，不执行宏。
